# 宿主机安装脚本

与参考项目 Incudal 一致，面板在每次下载请求中读取本目录的最新文件，再注入当前节点参数。模板内容不缓存在进程中，也不打包进 `dist/index.js`；修改这些文件后，下次下载立即使用新内容，无需重新构建或重启后端。

| 文件 | 用途 |
| --- | --- |
| `install.sh` | Incus 宿主机安装、存储与网络初始化、防火墙、证书信任及回调 |
| `install-ui.sh` | Incus 共用的终端交互菜单、存储检查与 RFW 规则参数生成，每次下载嵌入主脚本 |
| `node-uninstall.sh` | Agent / RFW 独立卸载、Incus 节点清理与二次确认，共用于安装脚本与本地维护命令 |
| `node-manage.sh` | 不含令牌和证书的本地维护入口，安装时保存至 `/usr/local/sbin/paledove-node` |
| `caddy.sh` | Caddy 安装、面板证书认证与回调 |
| `agent-install.sh` | 独立 Agent 安装入口 |
| `agent-setup.sh` | Incus 与独立 Agent 共用的下载、校验、配置与 systemd 安装函数 |

`@@PALEDOVE_变量名@@` 是面板注入的占位符，`${变量名}` 是 shell 表达式。不要直接执行原始模板，应执行面板生成的下载命令。参数转义和注入由 `src/services/agent/install-script.ts` 与 `src/install-template.ts` 负责；新增占位符时也要更新对应的参数映射。参数映射或后端逻辑发生变动时仍需构建并重启后端。

生产部署须将本目录与 `dist/` 一起部署，保持为 `server/templates/` 和 `server/dist/`。API 多副本部署时应同步更新各副本的模板文件。文件缺失或占位符未定义时下载请求失败，不回退到旧脚本。所有脚本下载接口禁止客户端和中间代理缓存。

刷新分为两种操作：

- **重新下载脚本**：读取最新模板。Incus 脚本每次下载还会签发新的 Agent 一次性安装令牌，支持在终端临时选择安装 Agent；之前未使用的 Agent 安装令牌作废。
- **重新生成命令**：Incus 与 Caddy 签发新的 24 小时安装令牌，旧命令失效。主动打开 Incus「重新安装」时同样签发新令牌；查看 Caddy 命令沿用仍有足够有效期的令牌。Agent 每次生成命令都替换该节点之前的一次性令牌，30 分钟内有效且仅可兑换一次。刷新不会更换已运行 Agent 的密钥，实际兑换令牌时才轮换密钥。

已经下载到宿主机上的脚本不会自动替换。更新模板后，重新执行面板中的下载命令才能获取新内容；若令牌已经使用或过期，先在面板重新生成命令。

Caddy 脚本重新执行时保留当前配置中的站点与存储设置，替换远程管理配置并强制重新加载，等待管理接口的服务端证书链校验通过后才回调面板。面板仍会校验服务端证书链，并在注册后同步面板管理的站点。注册或首次同步失败时保留有效安装令牌，脚本返回失败，可使用同一命令重试。

若出现 `certificate has expired`，先检查面板服务器与宿主机的 `date -u` / `timedatectl`，校准时间，再在宿主机详情的 Caddy 页重新生成并执行安装命令。脚本会等待证书刷新；失败时输出宿主机 UTC 时间、证书有效期及校验原因，并提示查看 `journalctl -u caddy-api`（使用备用服务时为 `paledove-caddy`）。若本地 CA 本身已过期或证书仍无法续期，应根据该日志排查，不能通过关闭 TLS 校验解决。面板客户端证书仍由开发者管理，过期时需要更新 `server/certs/incus/` 下的文件并重新执行安装脚本以更新信任。

Incus 脚本默认显示 `whiptail` 交互菜单，缺少组件时回退到文本菜单。通过 `/dev/tty` 读取输入，因此 `curl ... | bash` 也可交互。可选项包括 ZFS / Btrfs / LVM thin / dir、镜像文件容量或专用块设备、Agent、RFW、协议规则、GeoIP 黑白名单、访问日志及绑定网卡。协议规则与 RFW 下载源沿用 Incudal；勾选「所有入站」时覆盖其他协议选项。

主菜单同时提供「单独卸载 RFW」「单独卸载 Agent」「彻底卸载 Incus 节点」。也可传入 `--uninstall-rfw`、`--uninstall-agent` 或 `--uninstall` 直接进入对应确认界面，`--install` 直接进入安装向导。卸载在安装依赖之前执行，不运行 `apt-get update` 或安装软件包；`--yes`、`--non-interactive` 和 `PALEDOVE_NONINTERACTIVE=1` 均不能绕过卸载确认。

整机卸载默认取消，需要选择确认并再次输入大写 `YES`。它会删除**本机全部 Incus 项目**的容器、虚拟机、镜像、快照、卷、托管网络及存储池，然后卸载 Incus、Agent、RFW，清理本脚本的配置、Incus 数据与日志。卸载前应先在面板停用节点并备份数据。所有 Incus 操作强制使用本机 Unix socket；集群节点、无法连接的 Incus、资源删除失败、服务仍运行或存在残留挂载时停止清理，不强杀进程或强制跨挂载删除。Caddy、UFW 现有规则、通用存储工具和面板数据库记录保留；已移除的 sysctl 配置不会强制重置运行中的内核值。

安装向导确认后会写入本地维护命令 `sudo paledove-node`，无需有效安装令牌或面板在线即可进入卸载菜单。它只包含维护函数，不保存面板证书、节点安装令牌或 Agent 安装令牌。该命令在整机卸载后仍保留，便于重试未完成的清理；需要重新安装时在面板生成新安装命令。已有宿主机尚未安装该维护命令时，先从面板生成并下载新版脚本，再在新版脚本中选择卸载。

`bash -s -- --text` 强制使用文本菜单；`bash -s -- --yes`（或 `PALEDOVE_NONINTERACTIVE=1`）跳过交互并使用面板预设，RFW 规则沿用参考项目的默认 1–5 项与 CN 黑名单。无终端时必须显式使用无人值守模式。已有同名存储池直接复用；新建块设备池前检查挂载、交换分区和活动映射，并要求输入 `ERASE /dev/设备`。无人值守使用块设备还需设置 `PALEDOVE_ERASE_DEVICE=/dev/设备`。目录池不需要容量，目录留空使用 Incus 默认路径。

最终确认后才安装 Incus、创建存储与配置网络；菜单前仅安装基础依赖。跳过 Agent / RFW 或不启用新规则不会删除已安装组件或停止已有服务。安装完成后回读存储配置和组件状态并回传面板。Agent 安装令牌仅 30 分钟有效，交互或安装耗时过长导致失效时可从面板重新生成独立 Agent 安装命令。
