# 宿主机安装脚本

与参考项目 Incudal 一致，面板在每次下载请求中读取本目录的最新文件，再注入当前节点参数。模板内容不缓存在进程中，也不打包进 `dist/index.js`；修改这些文件后，下次下载立即使用新内容，无需重新构建或重启后端。

| 文件 | 用途 |
| --- | --- |
| `install.sh` | Incus 宿主机安装、存储与网络初始化、防火墙、证书信任及回调 |
| `caddy.sh` | Caddy 安装、面板证书认证与回调 |
| `agent-install.sh` | 独立 Agent 安装入口 |
| `agent-setup.sh` | Incus 与独立 Agent 共用的下载、校验、配置与 systemd 安装函数 |

`@@PALEDOVE_变量名@@` 是面板注入的占位符，`${变量名}` 是 shell 表达式。不要直接执行原始模板，应执行面板生成的下载命令。参数转义和注入由 `src/services/agent/install-script.ts` 与 `src/install-template.ts` 负责；新增占位符时也要更新对应的参数映射。参数映射或后端逻辑发生变动时仍需构建并重启后端。

生产部署须将本目录与 `dist/` 一起部署，保持为 `server/templates/` 和 `server/dist/`。API 多副本部署时应同步更新各副本的模板文件。文件缺失或占位符未定义时下载请求失败，不回退到旧脚本。所有脚本下载接口禁止客户端和中间代理缓存。

刷新分为两种操作：

- **重新下载脚本**：读取最新模板。Incus 脚本启用 Agent 安装时，每次下载还会签发新的 Agent 一次性安装令牌，之前未使用的 Agent 安装令牌作废。
- **重新生成命令**：Incus 与 Caddy 签发新的 24 小时安装令牌，旧命令失效。主动打开 Incus「重新安装」时同样签发新令牌；查看 Caddy 命令沿用仍有足够有效期的令牌。Agent 每次生成命令都替换该节点之前的一次性令牌，30 分钟内有效且仅可兑换一次。刷新不会更换已运行 Agent 的密钥，实际兑换令牌时才轮换密钥。

已经下载到宿主机上的脚本不会自动替换。更新模板后，重新执行面板中的下载命令才能获取新内容；若令牌已经使用或过期，先在面板重新生成命令。
